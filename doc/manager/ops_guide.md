# MetaSpace管理面使用流程
`MetaSpace`管理面的使用流程主要包含`fleet`的创建与管理，扩缩容策略的创建与管理，以及会话的接入与管理，以及服务的实时状态查询
详细`API`说明请参考`/doc/api/FleetManager.ymal`
## 创建fleet
1. 创建`fleet`: 调用`API`“创建应用进程队列” 配置`fleet`参数
    + **使用方式：** 构造请求（使用`postman`/`curl`等形式）
    + **fleet参数：** 例如`region`，实例带宽，`buildid`，入站许可，实例规格等。详见`fleetmanager`的`api`文档
    + **API返回参数：** `fleet_id`，及其他配置参数
    + **说明：** 调用`API`后内部执行涉及操作：准备账号资源，准备账号镜像，准备VPC资源，准备弹性伸缩组
2. 查询是否创建成功：调用`API`"查询应用队列基本信息”
    + **创建成功标志：** `API`的`Response`“`state`”参数为`ACTIVE`
    + **说明：** 服务会循环等待应用进程队列启动，启动成功后会更新应用队列状态，并返回`ACTIVE`状态
3. 修改`fleet`队列容量：调用`API`“更新应用队列容量”，配置参数
    + **使用方式：** 构造请求（使用`postman`/`curl`等形式）
    + **fleet参数：** 更新初始的最小/最大/期望实例数
    + **说明：** 关系到托管应用的预留资源设置情况

## 配置扩缩容策略
1. 设置弹性伸缩策略：调用`API`“创建弹性伸缩策略”	
   + **使用方式：** 构造请求（使用`postman`/`curl`等形式） 
   + **参数举例：** `fleet_id`，伸缩策略名称，策略具体内容（可用会话比达到多少开始扩容/缩容）
   + **API返回参数：** 弹性伸缩策略id，策略详情，`fleet_id`等"
   + **说明：** 可用会话比指所有管理的实例下，目前已使用的服务端会话/总服务端会话容量
2. 查询是否创建成功：调用`API`“获取弹性伸缩配置列表”查询弹性伸缩策略 	
   + **使用方式：** 构造请求（使用postman/curl等形式） 
   + **参数举例：** `fleet_id`，能否自动弹性伸缩，服务器会话保护策略等
   + **API返回参数：** 弹性伸缩策略id，策略详情，`fleet_id`等"
3. 设置自动扩缩容: 调用API “更新应用队列基本信息”
   + **使用方式：** 构造请求（使用postman/curl等形式） 
   + **参数举例：** `fleet_id`，能否自动弹性伸缩，服务器会话保护策略等
   + **API返回参数：** 弹性伸缩策略id，策略详情，`fleet_id`等"
   + **说明：** 默认创建`fleet`后会关闭自动扩缩容，需要在配置策略完成后调用`API`进行开启；”更新应用队列基本信息“的`API`也可用于更新`fleet`中其他参数，如最大/最小实例数量等
4. 查询是否自动扩缩容设置成功：调用`API`“获取弹性伸缩配置列表”
   + **使用方式：** 构造请求（使用`postman`/`curl`等形式） 
   + **参数举例：** `fleet_id`
   + **API返回参数：** 弹性伸缩策略个数，伸缩策略列表

## 服务实时状态查询
1. 查询队列状态：
   + **查询当前有哪些队列**：调用`API`“查询应用进程队列列表”
   + **查询当下队列的属性设置**（如激活状态、应用包id查询）：调用`API`“查询应用队列基本信息”
   + **查询当前队列的安全组设置信息**：调用`API`“获取应用队列入站规则”
   + **查询当前队列下的进程配置信息**：调用`API`“查询应用进程队列运行配置”
   + **查询当前队列中实例数设置**（最大/最小/目标实例）：调用`API`“获取应用进程队列容量的信息”
2. 查询进程状态：
   + **查询当下队列中进程情况**：调用`API`“获取处于不同状态的应用进程数量信息”
3. 弹性伸缩策略情况：
   + **查询当前使用的策略内容**：调用`API`"获取弹性伸缩配置列表"
4. 服务端会话情况：
   + **查询服务器会话状态及设置**：调用`API`“获取服务器会话详情”
   + **查询多少个服务端会话及状态**：调用`API`“获取服务器会话列表”
5. 客户端会话情况：
   + **查询服务器会话状态及设置**：调用`API`“获取客户端会话详情”
   + **查询多少个客户端会话及状态**：调用`API`“获取客户端会话列表”
